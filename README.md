# speedcheck

Консольная утилита для измерения реальной скорости загрузки данных по заданному HTTP/HTTPS URL. Программа выполняет серию последовательных GET-запросов и вычисляет агрегированную пропускную способность канала. Потребление оперативной памяти зафиксировано на уровне O(1) за счет потоковой передачи данных.

## Требования

- Python 3.12+

## Установка и запуск

### Вариант 1 (рекомендуемый, через uv)

```bash
uv sync
uv run speedcheck <URL>
```

### Вариант 2 (через venv и pip)

```bash
python3 -m venv .venv
source .venv/bin/activate  # Для Linux/macOS
# .venv\Scripts\activate   # Для Windows

pip install .
speedcheck <URL>
# Либо прямой запуск скрипта:
python speedcheck.py <URL>
```

### Пример запуска

```bash
speedcheck https://speed.cloudflare.com/__down?bytes=1000000
```

### Параметры командной строки

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `url` | `str` | *обязательный* | Адрес целевого ресурса (`http://` или `https://`) |
| `-n`, `--requests` | `int` | `10` | Количество последовательных запросов |
| `-t`, `--timeout` | `float` | `30.0` | Таймаут одного запроса в секундах |
| `-q`, `--quiet` | флаг | `False` | Отключение построчного вывода промежуточного прогресса |

## Единицы измерения

- Основная единица измерения — **Mbps (Мбит/с)**, дополнительно в скобках приводится **MB/s (МБ/с)**.
- Используется десятичная система SI: `1 MB = 1 000 000 байт`, `1 Mbps = 1 000 000 бит/с` (`Mbps = MB/s × 8`).
- Скорость рассчитывается как суммарный объем принятых байтов, деленный на совокупное время выполнения всех запросов (`total_bytes / total_seconds`). Это исключает математическое искажение среднего значения при неравномерной длительности отдельных запросов.

## Принятые технические решения

- **Потоковое чтение чанками по 64 KiB через `iter_raw()`**: гарантирует постоянный объем используемой памяти O(1) и фиксирует реальные сетевые байты без искажений от распаковки gzip/br в памяти процесса.
- **Заголовки `Accept-Encoding: identity` и `Cache-Control: no-cache, no-store`**: предотвращают сжатие данных сервером и исключают получение ответов из кэша промежуточных прокси-серверов.
- **Переиспользование TCP-соединения**: использование единого `httpx.Client` на всю серию запросов с поддержкой `follow_redirects=True` и валидацией кодов ответа через `raise_for_status()`.
- **Точный замер времени**: использование монотонного системного таймера `time.perf_counter()`.
